# 登录安全与管理员限制功能实现总结

## 功能概述

本次实现了两个重要的安全功能：
1. **登录安全机制** - 密码错误次数限制与账号冷却
2. **管理员操作限制** - 禁止admin用户修改任何用户信息

---

## 功能1: 登录安全机制

### 需求描述
一个账号在一天内若密码错误超过10次，账号将被冷却5分钟（每次错误都会显示提醒），登录成功后刷新次数。

### 实现细节

#### 1. 数据库迁移

**新增字段** (users表):
- `failed_login_attempts` (INTEGER) - 当天失败次数，默认0
- `last_failed_login` (TIMESTAMP) - 最后一次失败登录时间
- `login_locked_until` (TIMESTAMP) - 锁定截止时间
- `last_login_date` (DATE) - 最后登录日期（用于每日重置）

**迁移脚本**: `/backend/scripts/migrate_add_login_security_fields.py`

**执行方式**: 使用Python sqlite3直接执行ALTER TABLE命令

#### 2. 后端实现

**文件**: `/backend/app/routes/auth.py`

**配置常量**:
```python
MAX_LOGIN_ATTEMPTS = 10  # 最大失败次数
LOCKOUT_DURATION_MINUTES = 5  # 冷却时间（分钟）
```

**核心函数**:

1. **check_login_cooldown()** - 检查账号冷却状态
   - 检查是否在冷却期内
   - 自动重置每日计数器（通过比较last_login_date）
   - 返回用户ID和错误消息（如果在冷却期）

2. **record_login_failure()** - 记录登录失败
   - 增加失败次数
   - 更新最后失败时间和日期
   - 如果达到最大次数，设置冷却期
   - 返回当前失败次数和是否被锁定

3. **reset_login_attempts()** - 重置失败次数
   - 登录成功后调用
   - 清空所有失败记录和冷却状态

**登录流程** (6步):
1. 检查是否在冷却期内
2. 验证用户名和密码
3. 检查账号状态（pending/disabled）
4. 登录成功后重置失败次数
5. 创建JWT访问令牌
6. 构造响应数据

**错误消息**:
- 用户名不存在: "用户名不存在"
- 密码错误（未锁定）: "密码错误，今日还可尝试 X 次（超过10次将锁定5分钟）"
- 密码错误（已锁定）: "密码错误次数过多，账号已被锁定 5 分钟" (HTTP 429)
- 冷却期内: "账号已被锁定，请在 X 分钟后重试" (HTTP 429)

#### 3. 前端实现

**文件**: `/frontend/src/pages/Login.jsx`

**修改内容** (lines 47-51):
```javascript
} else if (error.response?.status === 429) {
  // 账号锁定/冷却期
  const detail = error.response?.data?.detail || '操作过于频繁，请稍后再试'
  message.error(detail, 5) // 显示5秒，因为是重要提示
}
```

**用户体验**:
- 401错误: 显示具体错误（用户名不存在/密码错误+剩余次数）
- 429错误: 显示锁定消息，持续5秒（重要提示）
- 403错误: 账号状态异常（待审核/已禁用）

### 技术亮点

1. **每日自动重置** - 使用date比较实现每日计数器重置，无需定时任务
2. **UTC时区处理** - 所有时间戳使用UTC，避免时区问题
3. **详细用户反馈** - 明确告知用户剩余尝试次数和冷却时间
4. **安全第一** - 429状态码符合REST标准，防暴力破解

## 功能2: 管理员操作限制

### 需求描述
admin用户不可修改任何用户信息（包括自己）。

### 实现细节

#### 受限端点 (6个)

**文件**: `/backend/app/routes/users.py`

1. **PUT /users/me** (line 97-102)
   - 限制admin用户修改自己的个人信息（邮箱、部门、头像）

2. **PUT /users/me/password** (line 138-143)
   - 限制admin用户修改自己的密码

3. **PUT /users/{user_id}/status** (line 184-189)
   - 限制admin用户更新任何用户的状态（pending/active/disabled）

4. **PUT /users/{user_id}/role** (line 220-225)
   - 限制admin用户更新任何用户的角色（user/admin）

5. **POST /users/{user_id}/reset-password** (line 263-268)
   - 限制admin用户重置任何用户的密码

6. **DELETE /users/{user_id}** (line 299-304)
   - 限制admin用户删除任何用户

#### 实现代码

每个端点开头添加统一检查：
```python
# 防止admin用户修改任何信息（包括自己）
if current_user.username == "admin":
    raise HTTPException(
        status_code=status.HTTP_403_FORBIDDEN,
        detail="admin用户不可修改用户信息"
    )
```

#### 错误响应
- **HTTP 403 Forbidden**
- **错误消息**: "admin用户不可修改用户信息"

### 技术亮点

1. **统一检查逻辑** - 所有端点使用相同的检查代码，易于维护
2. **早期验证** - 在端点最开始就进行检查，避免不必要的数据库操作
3. **明确错误消息** - 用户清楚知道为什么操作被拒绝
4. **完整覆盖** - 包括自我修改和修改他人两类操作

## 安全考虑

### 登录安全

1. **防暴力破解**: 10次失败后5分钟冷却，有效防止密码暴力枚举
2. **每日重置**: 防止长期积累的失败记录影响正常用户
3. **明确反馈**: 告知用户剩余尝试次数，平衡安全与用户体验
4. **UTC时区**: 避免夏令时和跨时区问题
5. **分离检查**: 区分"用户不存在"和"密码错误"，便于用户排查问题

### 管理员限制

1. **最小权限原则**: admin用户不能修改任何信息，防止误操作
2. **审计友好**: 所有限制操作返回403，便于日志审计
3. **代码集中**: 统一检查逻辑，降低遗漏风险
4. **早期验证**: 最先进行权限检查，避免不必要的资源消耗

## 已知限制

1. **admin用户完全只读**
   - admin用户连自己的信息都不能修改
   - 如需修改，必须使用其他管理员账号操作或直接修改数据库

2. **冷却期不可手动解除**
   - 只能等待5分钟自然过期
   - 紧急情况下可通过数据库直接清除锁定状态：
     ```sql
     UPDATE users
     SET failed_login_attempts = 0,
         login_locked_until = NULL
     WHERE username = 'target_user';
     ```

3. **用户名区分大小写**
   - 当前实现中 "Admin" ≠ "admin"
   - 仅 "admin" 用户名（小写）受到限制
